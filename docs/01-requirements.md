# 01 需求规格说明书（SRS）

版本：v1.0 ｜ 日期：2026-10-01 ｜ 状态：基线

> 本仓库公开。文中所有网点名、人名、账号、邮箱、内网地址均以占位符表示；真实值只存在于部署机的私有配置中。

## 1. 背景

网点资金分散在线上（中天预付款账户）和线下（6 个银行/支付宝/微信账户，以及门户“网点日记账”人工登记）。
现有三套采集已在运行：中天预付款流水监控、银行短信/支付宝/工行采集对账、门户日记账；但没有任何地方把它们合在一起回答：

1. **钱从哪来、到哪去了？**（来源与去向）
2. **每个账户今天的余额对不对？**（逐账户核对）
3. **网点今天赚钱还是亏钱？**（利润，特别是亏损要及时提醒）

前一版系统（2026-09 由其他工具开发）交付了只读采集和账面余额日报，但：逐笔对账覆盖率约 0.05%；利润始终为空；预警未接入；一天的日报静默丢失且无日志；报表被用户评价为“完全不是给用户看的”。本项目从需求重新出发重建，旧代码只作参考。

## 2. 干系人与角色

| 角色 | 说明 | 主要诉求 |
| --- | --- | --- |
| 网点负责人（用户） | 系统所有者、最终决策人 | 每天一眼看懂资金和盈亏；异常及时提醒；尽量少介入 |
| 财务/核对人 | 日常登记日记账、周末核对手工账户 | 清楚知道要处理哪几笔、录入实际余额 |
| 运维（本系统维护者） | 部署、升级、排障 | 失败可见、可重跑、可回滚 |
| 其他网点（后期） | 复用本系统 | 改配置即可部署，无需改代码 |

## 5. 功能需求

### FR-1 数据采集
- FR-1.1 所有 zto-cli 调用经统一客户端：主源失败（网络/超时/5xx/业务码非 200）自动切备源；端点在备源缺失时标记该源“不可用”而非报 0。
- FR-1.2 每个来源按“业务日”增量采集，支持任意日期区间回补（backfill）；同一数据重复采集结果不变（幂等，按 `来源+来源主键` 去重，内容变化则更新并留痕）。
- FR-1.3 每次采集记录：来源、日期、行数、状态（成功/空/失败）、错误原因、耗时。失败的来源不得被当成 0。
- FR-1.4 上游 SQLite 只读打开，绝不写入上游项目。
- FR-1.5 采集与对账解耦：采集成功入库后，对账/报表可独立重跑。

### FR-2 统一数据模型
- FR-2.1 所有流水归一为统一流水表（字段见 `03-data-model.md`），金额以“分”为整数存储，杜绝浮点误差。
- FR-2.2 统一科目体系：以门户科目为一级依据（中天与日记账已带科目），银行/支付宝按对方与已有分类映射；规则可在控制台维护，命不中进入“待分类”。
- FR-2.3 账户主数据：中天主账户 + 6 个线下账户；每个账户记录类型（对公卡/个人卡/支付宝/微信/现金）、数据来源（自动采集/人工登记）、是否含个人资金、是否参与余额核对。

### FR-3 对账
- FR-3.1 **重复识别**：日记账登记 ↔ 银行/支付宝自动采集，同账户、同方向、金额相等、时间窗口内（默认 ±2 天）唯一匹配 → 判为同一笔，以自动采集为准，日记账标“已对上”。多候选进入待核。
- FR-3.2 **互转识别**：两个本网点账户之间一出一入（含对公卡→中天充值、支付宝→其他账户、中天提现→收款账户）→ 判为内部划转，不计入收入/支出；手续费差额单列。
- FR-3.3 **中天提现跟踪**：每笔中天提现须在 N 天内（默认 3 天）找到对应入账；按提现发起人归集；超期未找到 → 预警并列入“提现去向待确认”。
- FR-3.4 **逐账户余额核对**：每账户每日 `期初 + 收入 − 支出 = 期末`，并与独立来源报告余额（银行短信余额、支付宝官方余额、中天汇总期末、门户日记账余额）比较；差额 ≠ 0 标红并说明可能原因。仅由同一来源推导、无独立对照的账户如实标“无独立对照”，不得显示为“已核平”。
- FR-3.5 **人工处理**：待核项在控制台可标记为 重复 / 互转 / 正常收支 / 忽略，并填写说明；人工结论持久保存，重跑对账时优先应用。
- FR-3.6 对账结果是“原始流水 + 规则 + 人工结论”的纯函数：任何时候重跑同一日期结果一致。

### FR-4 网点财务总表（按日/周/月）
- 两域（线上/线下）收入、支出、净额；内部划转额；重复剔除额。
- 现金头寸：7 个账户期末余额及合计（标明哪些已独立核对）。
- 经营利润（FR-5）、对账质量（已对上/待核/未匹配笔数和金额）、数据完整性状态。

### FR-5 利润
- FR-5.1 **现金口径经营利润（主）** = 已分类的经营收入 − 经营成本/费用；剔除内部划转、充值、提现、往来款。来源：中天科目分项 + 线下账户已分类收支（去重后）。按科目输出利润表（收入结构、成本结构）。
- FR-5.2 **账单口径利润（对照）**：沿用财务晨报口径（进港收入 + 返利 − 进港支出 − 出港费用 − 违规成本），与现金口径并列展示并解释差异来源（时间差、未接入科目）。
- FR-5.3 未分类金额单列，不悄悄计入或丢弃；未分类占比过高时报表提示“利润可信度降低”。

### FR-6 报表
- FR-6.1 日报（每日，数据日=昨日）、周报（上一自然周）、月报（上一自然月）。
- FR-6.2 **面向人阅读**：第一屏回答“今天赚/亏多少、钱在哪、有什么要处理”；中文业务语言，不出现技术状态码、哈希、内部术语；金额千分位、负数红色；手机可读。
- FR-6.3 日报内容：结论一句话；关键数字（经营利润、收入、支出、现金头寸、较昨日变化）；需要处理的事项（≤10 条，带金额和建议动作）；账户余额核对表；利润表（科目结构）；资金去向（划转、充值、提现）；对账结果；数据完整性；财务分析。
- FR-6.4 周报/月报增加趋势（每日利润、余额曲线）、环比、科目结构变化、对账质量趋势；月报附 CSV。
- FR-6.5 某来源缺失时报表照常生成，但醒目标注缺失来源与受影响指标（不补零、不隐藏）。
- FR-6.6 输出：自包含 HTML（离线可开）+ 同源 JSON；月报另附 CSV。

### FR-7 推送
- FR-7.1 知识库发布（沿用现有知识库 Agent 接口），发布后回读校验内容一致。
- FR-7.2 邮件发送到配置的收件人（Mac 正式机用 agently-cli；其他环境可用 SMTP），正文含关键数字与知识库链接，附 HTML。
- FR-7.3 每个报表每渠道只成功投递一次；失败可在补跑时补发；投递状态可在控制台查看。
- FR-7.4 企微/飞书通道预留，默认关闭。

### FR-8 预警
| 级别 | 规则（默认值可配置） |
| --- | --- |
| 高 | 当日现金口径经营利润 < 0；连续 3 天为负升级为“持续亏损” |
| 高 | 有独立对照的账户余额差额 ≥ 100 元 |
| 高 | 日任务失败或任一必需来源连续失败 |
| 中 | 账户余额低于阈值（中天主账户默认 5,000 元，其他 1,000 元） |
| 中 | 中天提现超过 3 天未找到入账 |
| 中 | 单笔未匹配 ≥ 500 元，或当日未匹配合计 ≥ 2,000 元 |
| 低 | 未分类金额占比 ≥ 5%；出现新科目/新结算类型 |
- 预警写入预警表，带冷却期与幂等键，不重复轰炸；当前渠道 = 邮件 + 日报“需要处理”区块（企微/飞书预留）。

### FR-9 财务分析
- 内置规则分析：利润驱动（收入/成本前五变化）、费用率、异常科目、余额趋势与可支撑天数、对账质量。
- 可选大模型分析（配置开启）：输入为汇总 JSON，输出必须只引用输入中的数字；失败不影响报表。

### FR-10 本地网页控制台（Mac/Windows 浏览器访问本机）
- 10.1 总览：最近 30 天利润、余额、数据状态。
- 10.2 报表浏览与下载。
- 10.3 待核清单：逐条处理（标记重复/互转/归类/忽略 + 说明），批量处理。
- 10.4 手工账户余额录入（周末核对），录入后参与余额核对。
- 10.5 科目映射与账户配置维护。
- 10.6 运行与投递状态、手动触发采集/对账/报表/补发。
- 仅监听本机地址；局域网访问需显式开启并设置口令。

### FR-11 日记账写入（后期，默认关闭）
- 仅在用户开启后可用；流程：生成写入计划（dry-run）→ 控制台人工确认 → 执行单源写入 → 回读校验 → 审计记录；超时不自动重试、不换源重发。

### FR-12 调度与运维
- 每日 12:10 日报、18:00 补跑（仅对失败或数据不完整的日期）、周一 12:20 周报、每月 3 日 12:30 月报（时刻可配置）。
- macOS 用 launchd，Windows 用任务计划程序，由安装命令自动生成。
- 每次运行写运行记录与日志文件；**任何失败都有日志、运行记录和邮件提醒**。
- `doctor` 自检：配置、凭据、来源连通、数据库完整性、调度状态。
- 数据库每日自动备份，保留 30 天。

### FR-13 可插拔与多网点
- 数据源以接口实现，配置决定启用哪些来源及实现（例如日记账改为表格/飞书导入只需换实现）。
- 网点、账户、阈值、科目规则、推送目标全部配置化；代码中零网点信息。

## 7. 验收标准（系统级）

1. 用 2026-09 全月历史数据回放：30 份日报全部生成；有独立对照的账户每日余额核对差额为 0 或给出明确原因。
2. 日记账与银行重复登记自动识别率 ≥ 95%（以人工抽查 10 天为准，每天与人工差异 ≤ 1 笔）。
3. 现金口径经营利润与门户中天科目汇总逐日可追溯一致；账单口径对照并列可见。
4. 构造亏损日、低余额、余额不平、来源失败样本，预警均触发且冷却生效。
5. 日报经用户阅读确认“看得懂、用得上”。
6. Mac 与 Windows 上 CI 全绿；在 Windows 上可完成安装、手动运行与调度注册（至少一次真实或虚拟机验证）。
7. 本机连续自动运行 7 天，无静默失败；之后部署正式设备连续 14 天，KB 与邮件各 ≥ 12 天成功。

## 8. 业务口径确认（2026-10-02 用户答复）

| # | 问题 | 用户答复 | 系统处理 |
| --- | --- | --- | --- |
| Q1 | 中天“线下提现”去向 | 承包区/业务员通过预付款账户提现，属于劳务费用（工资） | 计入人工成本；按掌中通账号自动查姓名展示；个别发起人可配置为转入本网点账户 |
| Q2 | 每月 20 日前后的工资、驿站入库费 | 付的是上月直营员工（含行政）工资；驿站入库费是付给驿站的派费 | 归入上月成本（按业务期间）；驿站入库费单列“驿站派费” |
| Q3 | 出纳账户收到的月度大额“收入” | 店主把上月店主支付宝收入汇总后转给出纳，不是新收入 | 识别为“余额宝 → 出纳”内部划转，不重复计收入 |
| Q4 | 对公卡定期付中通总部 | 购买电子面单单号与热敏纸 | 与中天充值匹配不上的，计入面单/物料成本 |
| Q5 | 店主支付宝每日转出 | 自动转入余额宝 | 新增虚拟账户“店主余额宝”，转入转出为内部划转；余额以首次人工录入为起点推算 |
| Q6 | 客户月结款 | 一般是上月运费；多付部分线下返还登记为其他支出 | 利润按业务期间计：优先采用日记账“业务发生时间”，财务规范登记后自动计入对应月份；控制台可人工指定 |

利润口径因此调整为：**经营利润按业务期间（权责）计，现金口径与账单口径作对照**；亏损预警改为“账单口径连续 3 天亏损（重要）”与“每月 25 日后本月至今经营亏损（紧急）”；月报 3 日出初版、25 日出定稿。
